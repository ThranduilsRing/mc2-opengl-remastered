# Host tool inventory

Game slots default to one engine: `MC2_HOST_CORES_PER_SLOT=2` gives each slot two physical cores (four logical CPUs).
Enable concurrency with `MC2_HOST_GAME_SLOTS=3` only after concurrent strict-chain validation passes.
`MC2_HOST_GAME_SLOTS` accepts 1..floor(6/width); physical cores 2..7 are available, CPUs 0..3 stay free.
`MC2_HOST_LEASE_EXCLUSIVE=1` (or `host_lease hold --exclusive --tag X`) reserves all six cores for timing proofs.
FIFO tickets block later requests behind an exclusive waiter; dead holders/tickets recover automatically.
Normal offscreen launches default to 854x480; declared capture sizes remain authoritative.
Install leases still serialize a shared install: concurrent runs require separate install copies and output files.

## Usage and related evidence

`py -3 tools/host_inventory.py --json` emits the same snapshot and provenance as JSON; `--output <path>` saves it.
Exit 0 means the inventory completed, including missing optional tools; exit 2 means input/probe/output failure.
Standalone RenderDoc and qrenderdoc's embedded API are separate probes.
SDK Python capture launchers are covered by [LunarG capture tools](https://vulkan.lunarg.com/doc/view/latest/windows/capture_tools.html).

[proof ledger](../tools/verified.py), [caller inventory](../tools/callers.py).

Caller evidence covers statically resolved imports and executable command positions; docs and generated files never satisfy the check.

Exceptions are explicit baseline entries, not evidence of live use; new uncalled scripts fail until reviewed.
The fixed delivery-input union in callers.py keeps these unstaged tools/tests identical before and after coordinator staging.

## Vulkan layers from the SDK: validation and GFXReconstruct

Both layers come from the Vulkan SDK rows above; the loader finds them through the SDK installer's registration or `VK_LAYER_PATH` (the SDK `Bin`).
- Validation (`VK_LAYER_KHRONOS_validation`): a Vulkan smoke run with `MC2_VULKAN_VALIDATION=1` grades every message of the layer,
  an error is the red bucket `vk_validation_error`. Recipe, counts and the report line: [Vulkan validation](vk-validation.md).
- GFXReconstruct capture/replay proof: `py -3 tools/visual_verify/vk_replay.py proof --install <install> --bookmark <stem> --out <dir>`.
  `capture` runs one Vulkan bookmark capture (`tools/visual_verify/capture.py` with the Vulkan umbrella, so the engine goes through the harness: background-only,
  host lease) with `VK_INSTANCE_LAYERS=VK_LAYER_LUNARG_gfxreconstruct`, `GFXRECON_CAPTURE_FILE` and `GFXRECON_CAPTURE_FRAMES` set (the variables
  `gfxrecon-capture-vulkan.py` sets; `vk_replay.py env` prints them), `replay` runs `gfxrecon-replay --swapchain offscreen --screenshots <frames>` under the same
  lease (no surface and no window: `--wsi headless` still tries the captured Win32 surface and fails), and `compare` hashes the decoded RGB pixels of the engine's own PNG of the presented frame (the live frame) and of every replayed frame:
  exit 0 when one replayed frame equals the live one, 1 when none does, 2 when a tool failed. `--dry-run` prints the commands.
  The SDK's capture and replay tools have no compare mode of their own; the hash comparison is this script's.

## Harness tooling

- `py -3 scripts/check-staged-hygiene.py --staged` (alias of `--index`): pre-commit scan of the index for new control bytes (0x00, 0x08, ...), mixed endings and CRLF/LF flips of tracked files; the board runs `--range`.
- `tools/sim_determinism.py run|check|pairs-until-fail` and `tools/saveload_roundtrip.py resave|baseline|check|run` accept `--ref-exe PATH` / `--ref-commit SHA` and forward them to every run_smoke.py child (the fingerprint reference of an A/B exe).
- run_smoke host-load gate (`scripts/smoke_lib/host_load.py`): after the host lease and before any launch, another engine, a compiler/linker burst above `MC2_HOST_LOAD_BUILD_MAX` (4) or MsMpEng above `MC2_HOST_LOAD_DEFENDER_PCT` (150) is named in one line and waited out up to `MC2_HOST_LOAD_WAIT_S` (120 s), then the run launches anyway; report.json `host_wait` records the lease and load waits (neither counts against a mission budget). `MC2_HOST_LOAD=off` skips it.
- Batch lease: `py -3 scripts/smoke_lib/host_lease.py hold --tag X [--ttl S]` parks the host lease in a holder process; runs started with `MC2_HOST_LEASE_BATCH=X` enter it, everyone else waits; `release --tag X`, the TTL (max 6 h) or a dead holder pid ends it.
- `tools/tracy_capture_compare.py capture|baseline|regress|selfcheck|matrix` hold the host lease from before the first child to after the last; `--warmup-seconds N` adds one unrecorded launch of a freshly copied exe; the vk arm no longer forces `MC2_VK_SHADOW_INTEROP=0` (engine default; pass `--env` to pin an island).
- `scripts/parent_watchdog.py` `ParentWatch().gone()`: unbounded polling loops stop when the process that started them exits (TaskStop kills the shell, not always its child). Inventory 2026-10-15: no tracked script runs `tail -f`; the two unbounded pollers, `tools/dev_shell/watch.py` and the `scripts/game_auto.py` recorder, carry it; every other loop in scripts/ and tools/ is deadline-bounded.
- `--sim-speed N` (1..4) on `tools/sim_determinism.py run|check|pairs-until-fail`, `tools/saveload_roundtrip.py` and run_smoke sets `MC2_SIM_SPEED=N`: under the fixed-step clock, after mission_ready and while the window lacks focus, the engine runs N 1/30 s steps per drawn frame (same step, same RNG draws).
