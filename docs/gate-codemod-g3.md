Generated by `py -3 tools/gate_codemod.py --family g3 --write`. **No C++ was changed.** Each row says what happens if the raw `getenv` read at `file:line` is rewritten to `mc2::gate::get<"MC2_X">()` against the gate row committed in `Gates/gate_table.json` (design `typed-gate-registry-design.md` section 5.7, review amendments 1, 2, 9). Scanned: commit `8fcffc06a` (files read from git, not the working tree).

How to read the verdicts:

* **NO-CHANGE** -- the old reader and the row answer identically for every probe input. Rewrite.
* **EDGE** -- differs only on `""`, `false`, other text, or (numeric) junk / out-of-range input. Rewrite and list the file in the PR; the byte-identical alternative is named in the row.
* **SEMANTICS** -- differs on unset, `"0"` or `"1"`, or on the default. The proposed text is the per-site override (`get<"N", Rule::R>()`), never Std, so behavior is byte-identical; converting it to the row rule is a separate named commit.
* **UNHANDLED** -- the tool could not prove the site; a human reads the code line.

Rows in the committed table still carry the legacy rule of their readers (`L(Presence, ...)` etc.), so NO-CHANGE here means "identical to the row as committed"; converting a row to Std is a separate named commit and would change these verdicts.

Probe inputs: **U** unset, **E** `""`, **Z** `"0"`, **F** `"false"`, **O** `"1"`, **X** `"yes"`, **X10** `"10"`, **X25** `"2.5"`. Caching shape is preserved: a `static const T s = <reader>` stays a static holding `get<>()`; a lambda static loses only the lambda.

Every file that gets a replacement needs `#include "Gates/gate.h"`.

## Caching check: per-call readers versus run-time writers

A typed `get<>()` caches its first answer, a per-call `getenv` does not. None of the 56 gates read per call in this plan is written into the environment by a literal `_putenv`, `putenv`, `setenv` or `SetEnvironmentVariable` in the tracked C++ sources (30 other gates are), so no per-call site needs a `reread` row. A write through a computed name is not seen by this check.

## Limits of this plan

* The interpreter in `scripts/gate_idioms.py` models C string reads only (`getenv`, `atoi`/`atol`/`atof`, character tests, `strcmp`); a site that needs more is UNHANDLED, never guessed.
* `inf`/`nan` and float-to-double rounding at a bound are modelled only through the `1e999` probe; `NaN` input is not probed.
* Harness impact reads `harnessValues` in the gate seed (values found in scripts, tests, tools, data). Launcher `offVal`s and installed `launcher_env.json` files are not in the seed.
* A replacement that drops a `const char*` local also drops the local's name, so the tool refuses when the pointer is used again.
