## 5. The burial audit — buildings settle, and nothing else moves

`scripts/object_burial_audit.py` (`6d9360046`, corrected at `632122f7d`) is a
line-by-line offline port of `MapData::terrainElevation()` (`mclib/mapdata.cpp:2189`).
It answers, without launching anything, **which elevation function the shipped
mission data was authored on**.

Across **all 72,153 stock objects on all 37 shipped maps, 0 unresolved rows**:
authored Z matches the **Phong-retired (plain)** heightfield to **≤ 0.0001 wu on
every class**, and disagrees with the **legacy CPU-Phong** heightfield by up to
**13.39 wu** on **48.8 % (GATE) – 96.5 % (TREE)** of objects. The shipped data was
authored on the plain triangle-linear heightfield. **That independently validates
the CPU Phong retirement (`a75339bb0`) — it was not a taste call.**

   would have passed *before* the fix too.
3. While step 2 runs: **no taskbar button, no Alt-Tab entry, no keystroke leakage.**
4. **An offscreen capture still produces real pixels, not black.** A fix that buys
   safety by breaking capture is not a fix.

> **⚠ Three ways to score this wrong.**
> **(a) Scoring a non-event as a pass.** An offscreen run shows nothing — no window,
> no taskbar entry. That is indistinguishable from *the engine having died two
> seconds in*, in which case your cursor is also free, for the wrong reason. **No
> `[CURSOR_GUARD]` line in the console ⇒ the check did not happen.** Step 4 is what
> converts a non-event into evidence.
> **(b) Running step 2 through `run-with-log.bat`.** Line 18 of that file sets
> `MC2_NO_CURSOR_GRAB=1` whenever `MC2_WINDOW_OFFSCREEN` is defined — correct for an
> interactive launcher, but it would free the cursor via the **old** arm and never
> exercise the new one. **A false pass.** `CURSOR-2-offscreen-alone.bat` invokes the
> executable directly and deletes both `MC2_NO_CURSOR_GRAB` and `MC2_SMOKE_MODE`
> first, so neither a leftover shell variable nor `launcher_env.json` can manufacture
> a pass. Step 3 also means you **cannot close it normally** — open Task Manager
> before you launch.
> **(c) Reaching for `MC2_LOG` and getting it backwards.** Both `CURSOR-*.bat` files
> already set `MC2_LOG=1`; do not "turn logging off" with `MC2_LOG=0`, which
> **enables** it (§1). And with it genuinely unset there is no console output at
> all, so trap (a) becomes unavoidable rather than merely likely.
>
> *(Incidental, found while checking the above: the FINAL folder also carries a
> stray `run-with-log - Copy.bat`. Verified by grep — it does **not** contain the
> line 18 `MC2_NO_CURSOR_GRAB` trap, so it is duplicate clutter rather than a second
> way to score a false pass. Still not a sanctioned route for any arm.)*

## 11. The hard-won rules

Compressed to the ones that cost real time. Each is here because a lane learned it
the expensive way.

1. **Read gate defaults from the C++ reader** — not docs, not commit messages, not
   the registry's `defaultOn` field. `MC2_TERRAIN_AMBIENT_FLOOR` was reported
   default-OFF by a checker purely because a *debug trace* line contained a bare
   `getenv` with no idiom attached. `scripts/build_review_pack.py` deliberately
   refuses to store defaults in its manifest and re-resolves them from source at
   render time for exactly this reason.

2. **Prove a check fires by injecting the real regression into the live tree.** A
   checker that has only ever seen the fixed tree has never been tested. Positive
   **and** negative control, both directions. The model is the ledger's Dispute 3:
   the same tool reported `dirty: false` on a clean image and `dirty: true` on a
   dirty one, so the scan is not one that always says "clean". §6 is what happens
   without this — five checks lying at once, and 631 tests that no gate ever ran.

3. **Use a private index in a shared worktree. `read-tree` and `commit` go in ONE
   shell invocation, and you clean up with `git restore --staged <your paths>` —
   never a blanket `git reset`.** Both halves of that sentence are corrections to
   what this file said in an earlier revision, and each cost a lane real time.
   ```sh
   # ONE invocation, start to finish:
   export GIT_INDEX_FILE=<scratch>/my.index
   git read-tree HEAD          # valid only while HEAD does not move
   git add <your paths>
   git diff --cached           # READ THIS
   git commit -F <msgfile>
   # then, separately:
   unset GIT_INDEX_FILE
   git restore --staged -- <your paths>   # NOT `git reset`
   git show --stat HEAD        # verify: only your files
   ```
   *Why a private index at all:* a pathspec commit against the shared index takes
   the whole working-tree file and will sweep in another lane's uncommitted edits.

   *Why one invocation:* **your index holds a full tree snapshot, so a `read-tree`
   is only valid while HEAD stays put.** If a parallel lane commits between your
   `read-tree` and your `commit`, committing that index **silently reverts every
   file they changed** — and `git show --stat` looks innocent, because it lists only
   files differing from the *new* parent. Splitting the recipe across two tool calls
   is exactly the window that lets HEAD move; keeping it in one closes it. A lane
   survived this by luck in `8b3e040bb` and had to prove after the fact that
   `git rev-parse 25008e321:scripts/check-contracts.sh` matched its own commit's
   blob.

   *Why not `git reset`:* a blanket `git reset` operates on the **shared** index and
   **discards every other lane's staged work** — it un-stages their files as well as
   yours. `git restore --staged -- <your paths>` touches only what you named. (An
   earlier revision of this file also called the shared-index litter "the acceptable
   price". It is not; it cost the next lane a diagnosis. Clean up — but clean up
   *narrowly*.)

4. **`git apply --unidiff-zero` can silently misplace a pure-insertion hunk.** With
   zero context there is nothing to anchor on, so the hunk lands at the stated line
   number whether or not that is still the right place. **Verify the result; the exit
   code means nothing.**

5. **A background build can report exit 0 while the link failed.** Check the
   artifact, not the status — and check the *fingerprint* of the artifact, not the
   generated header, which only records what cmake last stamped.

6. **Do not edit a shell script while it is running.** `bash` re-reads a running
   script by byte offset, so an edit mid-run makes it execute garbage. This produced
   spurious syntax errors twice in one night and probably explains several "races"
   diagnosed as something else. Applies to `scripts/check-contracts.sh` above all —
   coordinate, or wait.

7. **Say which route produced a number.** "Verified from the exe" and "verified from
   the manifest" are different strengths of claim and get different verdicts. Naming
   the route is the difference between a number that survives adjudication and one
   that gets retracted. Corollary: **a retraction needs the same standard of proof as
   a claim.** "I found a number with the same digits" is not a derivation — do the
   arithmetic and check it lands on the number before publishing provenance. An
   unnecessary retraction destroys a true result and costs the reader's trust in
   every other correction on the page.

8. **THE ROOT FAILURE — a lane measures a number, reports it, never commits the
   artifact, and the next lane grades it fabricated. Both lanes behaved correctly.**
   The repo is not a record of what was measured; it is a record of what was
   *committed*. This happened at least five separate times today, and it is why
   `.claude/MEASUREMENT-LEDGER.md` exists.

   Before writing "fabricated", check: untracked files (`git status --porcelain`, a
   leading `??`), sibling worktrees, sibling *installs*, commits that **pruned** an
   artifact after it was used (`git log --diff-filter=D`), and
   `git log --all --oneline -- <path>` — a file can be `??` in your worktree and
   committed on a ref you are not on.

   **The fix is one `git add`, in the same commit as the claim.** It caught itself
   live *again* tonight: `116854` — the assertion count that is the entire evidence
   for §6.3 — existed in **no file in the repo**, tracked or untracked, until this
   handoff pasted the verbatim run into §6.3.

9. **`$?` after a pipeline, or after an `&&` chain, is the LAST command's exit — not
   the one you care about.** `cmd | grep -c foo` exits **1** when the count is zero,
   so a chain built on it silently takes the wrong branch; that shape skipped a
   lane's commit outright today. Two habits close it: capture the code into a
   variable **immediately** (`out=$(cmd); rc=$?`, or `${PIPESTATUS[0]}` for the head
   of a pipeline), and never end an evidence-producing chain with `echo` — this
   lane's own background board reported "exit code 0" to the harness for exactly
   that reason while the board itself had exited 1.

10. **A replace-based "restore" is not a restore. Back up the bytes and prove it
    with a hash.** Injecting a regression and reverting it by string substitution
    assumes the string occurs once. In the A/B arms every gate appears **twice** by
    design — once in the common default block, once in the arm's override — so
    reverting `=0` to `=1` rewrote both, left every *effective* value correct, and
    passed `check-ab-kit.py`. Only a sha256 manifest taken before the injection
    caught it (§6.9). **Hash before, hash after, diff the manifests.**
