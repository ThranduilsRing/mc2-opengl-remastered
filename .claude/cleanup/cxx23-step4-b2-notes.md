## 2. B2.0: goldens and characterization tests FIRST (against the OLD classes; the same bodies run later against the new containers)
ORDER INSIDE B2.0 (RB2 section 14): the golden values (the HS2 tie table, the HP6 hashes) are generated by the OLD classes and committed as constants BEFORE any class is edited; the tests, the census and the probes follow. Files: `tests/unit/test_elist_contract.cpp`, `test_sortlist_contract.cpp`, `test_pqueue_contract.cpp` (heap_shim exists; SortList and PriorityQueue need a `Fatal` stub in `target_sources`); the golden generators and probe scripts live under `tests/analyze/` (lane 1; a script under `tools/` needs `check_conflict` first, lane 2 is live there).
- HE1 empty: `Begin()`/`End()`/`Find` on an empty list are INVALID (IsDone), `Count()` 0. HE2 `End()` is the tail element and a reverse loop with `--` stops through IsDone. HE3 postfix `++`/`--` return the new position. HE4 `Insert(x,iter)` goes BEFORE; `Insert(x,Pos)` is false for `Pos >= Count` incl. empty; `Insert(list,iter)` keeps source order before iter. HE5 `Delete(a,b)` is [a,b), `Delete(a,a)` asserts. HE6 ADDRESS STABILITY: a reference taken before Append/Insert/Delete-of-another is still valid (the property `vector` loses; the test states which lists need it and runs the same case on `std::deque`). HE7 copy/assign: deep for values, shallow for pointers; self-assign empties. HE8 `Find` uses `==`, first match, `Start_Index` must be < Count. HE9 `operator[]`/`Iterator(Pos)` are positional and O(n). HE10 `Count()` is 32-bit unsigned. HE11 `Append` with the heap down returns false (documented, not asserted). HE12 element destructors run head to tail on `Clear` (D15 pins this order in the new code).
- HS1 both directions. HS2 TIE TABLE: for n = 2..9 and for 200 and 4000 slots padded with sentinels, the exact qsort permutation of tie patterns (all equal, pairs, runs) is recorded and compared with "score, then fill slot"; the test pins how many patterns differ (the size of the SortList decision). HS3 `clear()` writes id = slot and +-3.4E38, and a sort whose sentinel sign does not match its direction puts the sentinels FIRST (the `MoverGroup::sortMovers` defect). HS4 `setId/setValue` ignore an out-of-range slot. HS5 id -1 round-trips. HS6 NaN scores: the old comparator is not a strict weak order (pinned as that). HS7 (new class, written with B2.4) `sort_scored`: NaN last in both directions even for TWO NaNs (`isnan` tested on both operands first), -0 equals +0, +-inf, denormals, slot tiebreak, ids keep their sign, equality with `std::stable_sort` on random inputs.
- HP1 min first. HP2 TIE ORDER: insert k equal keys with distinct ids in several interleavings with other keys and record the pop order. HP3 `change` both directions on ties. HP4 `find` returns the heap index of the FIRST match or 0. HP5 `clear` then reuse. HP6 GOLDEN SCRIPTS: 2,000 random scripts of 200 operations (insert/remove/change/find, keys 0..15 so ties dominate, A*-shaped) hashed (FNV-1a over the pop id sequence and the final array); the new heap must reproduce every hash. HP7 capacity: the old 5002nd insert is an out-of-bounds write (not asserted); the new heap is sized to its graph and the test says so.

## 3. Conversion rules (paste into the lane brief; RB2 section 13, replaces D1-D13)
- D1 Pointer and trivial elements: `std::vector`. By-value elements whose address escapes: `std::deque` behind an append-only API (no erase but `clear`, which states its precondition). Each list gets a one-line contract: order, who erases, address stability.
- D2 No class derives from a std container; EList-derived classes become composition with the narrow API the call sites use.
- D3 Range-for keeps the exact loop shape: every `break`, `continue` and non-short-circuit `|=` stays. No `any_of`/`all_of`/`find_if`/`||` over bodies with side effects (objective `Status`, `Execute`, `StatusChanged*`). Erase-while-iterating: `std::erase`/`std::erase_if`.
- D4 Any index or length from a save, a mod file or ABL goes through a checked accessor or a `std::span` with its real size: out of range = one log line + reject or clamp, never UB. ABL array parameters use `ABLi_popIntegerBuf()` (code name `ABLi_popIntBuf`, mclib/ablxstd_stack.cpp) (a span with the declared element count; precedent `ABLi_popCharBuf`, ablxstd_stack.cpp:89-98).
- D5 Sizes: `std::ssize` in comparisons, explicit casts at `long` targets, no warning suppression.
- D6 Snapshot getters return `std::vector<T*>` by value; nothing hands out `c_str()` or element pointers from a container that can grow.
- D7 No static-duration owner or scratch: sort buffers are locals sized to the domain bound (`MAX_MOVERS`, the weapon maximum, 5); the open list is a member of the solving object.
- D8 `mc2::sort_scored(std::span<Scored>, SortOrder)`: key (is_nan, directed score, fill slot ascending); `isnan` tested on both operands first; -0 == +0; documented in the header and at each call site. `calcOptimalRange` is an argmax + tie mask over 5 values, no sort.
- D9 The open list keeps the 1-based heap, the three sift rules and the linear first-match `find`; no sentinel, explicit bounds; capacity = graph size, reserved once; `findByKey`/`getItem` deleted; never `std::priority_queue`. The class is `mc2::PathOpenList` (or keeps the name with "index = heap position" stated).
- D10 Dead code leaves with its container after the bar of section 4 (B2.1): census rows 0 + `build_all_targets` rc 0 + a grep of inactive `#if` branches and `data/` (FIT keys, ABL scripts) + tag `step4-b2-pre`.
- D11 A header changes in the same commit as every includer the compiler reports; new headers are NEVER added to `mclib/mclib.h` (that would put `<cmath>` and `<algorithm>` into every TU that includes it).
- D12 Sole-owner lists (objectives) become `std::vector<std::unique_ptr<T>>` with an explicit `clone()`; logistics owners only in B2.2c, never in the same diff as the container swap.
- D13 CRLF preserved (`git ls-files --eol`); comments WHAT+WHY; touched regions lose `file:NNN` refs.
- D14 Behaviour changes on malformed input are listed in each commit (ruling 5, section 7b); a ruleset change (B2.4; B2.5-pre if hit) is its own commit with nothing else in it and is proven by the patched-old equivalence.
- D15 Destructor order that is observable is made explicit (HE12 pins head to tail); `std::vector` does not specify element destruction order.
- D16 Before a batch adds a standard header to a TU on `cmake/pch/pch_skip.cmake` (or to a header such a TU includes), an include-only commit is objhash-compared: IDENTICAL, or the overload-sensitive call is fixed explicitly first, in its own commit. `code/objective.cpp`, `code/group_goals.cpp` and `mclib/move.cpp` are on that list (pch_skip.cmake:119, 92, 69).
