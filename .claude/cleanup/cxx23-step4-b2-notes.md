## 2. B2.0: characterization tests to write FIRST (against the OLD classes; the same bodies run later against the new containers)
Files: `tests/unit/test_elist_contract.cpp`, `test_sortlist_contract.cpp`, `test_pqueue_contract.cpp` (heap_shim exists; SortList and PriorityQueue need a `Fatal` stub in `target_sources`). Golden numbers are generated by the OLD code in B2.0 and committed as constants BEFORE any class changes.
- HE1 empty: `Begin()`/`End()`/`Find` on an empty list are INVALID (IsDone), `Count()` 0. HE2 `End()` is the tail element and a reverse loop with `--` stops through IsDone. HE3 postfix `++`/`--` return the new position. HE4 `Insert(x,iter)` goes BEFORE; `Insert(x,Pos)` is false for `Pos >= Count` incl. empty; `Insert(list,iter)` keeps source order before iter. HE5 `Delete(a,b)` is [a,b), `Delete(a,a)` asserts. HE6 ADDRESS STABILITY: a reference taken before Append/Insert/Delete-of-another is still valid (the property `vector` loses; the test states which lists need it and runs the same case on `std::deque`). HE7 copy/assign: deep for values, shallow for pointers; self-assign empties. HE8 `Find` uses `==`, first match, `Start_Index` must be < Count. HE9 `operator[]`/`Iterator(Pos)` are positional and O(n). HE10 `Count()` is 32-bit unsigned. HE11 `Append` with the heap down returns false (documented, not asserted). HE12 element destructors run head to tail on `Clear`.
- HS1 both directions. HS2 TIE TABLE: for n = 2..9 and for 200 and 4000 slots padded with sentinels, the exact qsort permutation of tie patterns (all equal, pairs, runs) is recorded and compared with "score, then fill slot"; the test pins how many patterns differ (the size of the SortList decision). HS3 `clear()` writes id = slot and +-3.4E38, and a sort whose sentinel sign does not match its direction puts the sentinels FIRST (the `MoverGroup::sortMovers` defect). HS4 `setId/setValue` ignore an out-of-range slot. HS5 id -1 round-trips. HS6 NaN scores: the old comparator is not a strict weak order (pinned as that). HS7 (new class) `sort_scored`: NaN last in both directions, -0 equals +0, slot tiebreak, a capacity clamp reports the drop, ids keep their sign.
- HP1 min first. HP2 TIE ORDER: insert k equal keys with distinct ids in several interleavings with other keys and record the pop order. HP3 `change` both directions on ties. HP4 `find` returns the heap index or 0. HP5 `clear` then reuse. HP6 GOLDEN SCRIPTS: 2,000 random scripts of 200 operations (insert/remove/change/find, keys 0..15 so ties dominate, A*-shaped) hashed (FNV-1a over the pop id sequence and the final array); the new heap must reproduce every hash. HP7 capacity: the old 5002nd insert is an out-of-bounds write (not asserted; the new class grows and the test says so).
- B2.0 also adds: (a) the EList deprecation census exactly as in B1 (`[[deprecated("B2")]]` on the public API, uncommitted; build_all_targets; `cxx23-step4-b2-callsites.txt` with file:line:kind per TU incl. editor; each batch commit removes its rows; the board checks the count only falls); (b) probe P1 on the OLD exe (uncommitted patch applied by script): at every SortList sort call log site, n filled, whether the filled prefix holds equal scores, whether qsort's prefix order differs from (score, slot) order, and a hash of the output id sequence; (c) probe P2: per path solve log solver, start, goal, max open size (the legacy buffer holds 5001) and a hash of the pop sequence and of the final step list; (d) probe P3: per sim frame a hash of every objective status and flag (`CBooleanArray`) plus each `checkObjectiveStatus` result. ## 3. Conversion rules (paste into the lane brief)
- D1 The element decides the container: pointer or trivial elements `std::vector`; BY-VALUE elements whose address is stored or returned `std::deque` (push_back/pop_back keep references; a mid-list erase would need `std::list`, none exists today). Every list gets a one-line contract comment: order, who erases, address stability.
- D2 No class derives from a std container and no new derived container appears: the 5 game classes derived from EList become composition (`objectives`, `conditions`, `actions` members) with the narrow API the call sites use (range-for, `size()`, `append`).
- D3 Reads use range-for, reverse reads `std::views::reverse`, erase-while-iterating becomes `std::erase` / `std::erase_if` (the predicate may `delete` the pointee: the list never touches pointees). Nothing uses postfix `it++` for its value (grep clean; the census re-checks).
- D4 Positional access (`infos[idx]`) and any index that comes from a save, a mod file or ABL goes through a checked accessor: out of range = log line + reject, never UB (ruling 5).
- D5 Sizes: `static_cast<long>(v.size())` at every `long` target and `std::ssize` in comparisons; C4267/C4018/C4244 stay as errors where they are errors today; no suppression.
- D6 Snapshot getters (`getInventory`, `getForceGroup`) return `std::vector<T*>` BY VALUE and never append to a caller's list.
- D7 No static-duration scratch owner (sim-kernel design): sort scratch is a stack buffer (`ScoredBuffer<N>`); the A* open list is a value `mc2::IndexedMinHeap` with ONE named exception (the shared open list until the Mission-owned path system); `new SortList`, `new PriorityQueue` and their `delete`s disappear.
- D8 SORT ORDER (owner ruling): `mc2::sort_scored(std::span<Scored>, SortOrder)`; order = score in the requested direction, NaN last in both directions, -0 equals +0, ties by FILL SLOT ascending. `Scored` carries the slot, so `std::sort` on (score, slot) is a strict total order and needs no temporary buffer; `std::stable_sort` gives the same output and is the fallback. The rule is documented in the header and at each call site.
- D9 PRIORITY QUEUE: `mc2::IndexedMinHeap` keeps the 1-based layout and the SAME `upHeap`/`downHeap` rules (`>=` moves up, left child on equal children, stop on an equal key) with explicit loop bounds instead of a sentinel; it grows instead of corrupting; `findByKey`/`getItem` are deleted (no caller); `std::priority_queue` is NOT used (no decrease-key, different ties). Changing the tie rule is a separate, ruled commit (Q4).
- D10 Dead code goes with its container in the same commit: grep + the all-targets compile are the audit, tag `step4-b2-pre` first; no feature is removed.
- D11 A header changes in the same commit as every includer the compiler reports; `mclib/elist.h` stays until E-end; removing an include from `mclib/mclib.h` is checked by build_all_targets (transitive `heap.h`, `dstd.h`, `vfx.h` leave with sortlist/bitflag).
- D12 Pointee ownership: where the list is the SOLE owner (CObjective's four lists, CObjectives, probably `variants`/`inventory`) the element becomes `std::unique_ptr<T>` in the same diff so the delete loops vanish; views and snapshots stay raw (Q6).
- D13 Preserve CRLF files (`logisticspilot.cpp`, `team.cpp`, `mechlabscreen.h`, ...; `git ls-files --eol` after every edit); comments are WHAT+WHY; each touched region loses `file:NNN` refs.

## 6. What the gates cannot see, and the closing proof (summary of the table above)
SIMID covers movers (position, target, brain, move state, path step COUNT), buildings, turrets, ABL and RNG counts. It does NOT see logistics lists and their order, the deployed force before launch, UI text, objective status except through side effects, saved objective text, the CONTENT of a path (only where the mover ends up), contact lists that no brain consumed in the window, weapon order when nothing fires in the window, or anything after the baseline window. tier1 boots straight into missions (no logistics, no campaign flow). So each batch has one probe or round trip that observes the container output directly instead of its distant consequence (P1/P2/P3, the campaign round trip).
