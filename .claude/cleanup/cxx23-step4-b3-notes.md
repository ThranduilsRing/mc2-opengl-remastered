## 3. Conversion rules (paste into the lane brief)
- E1 A function that opens, reads and closes a file holds it as a LOCAL VALUE (`FitIniFile fit;`). The destructor already closes. Explicit `close()` calls stay where a second open of another object needs the handle first. No `new` for a file that does not leave the function.
- E2 An owner that outlives a function (a member, a registry slot) holds `std::unique_ptr<T>`. Members are declared so that destruction order equals teardown order, and the order is written beside the declaration. No static-duration owner (E10).
- E3 A `File*`, `FitIniFile*` or `PacketFile*` PARAMETER stays a raw pointer and means "borrowed, valid for the call". Nothing stores a borrowed pointer past the call.
- E4 The name is a `std::string` member; `const char* getFilename() const` returns `nullptr` when the file is closed (the old contract, `mech_loadout.cpp:61` tests it) and otherwise points into the member, valid until the next `open`/`close` of that same object. A child COPIES its parent's name (no shared pointer). All 20 `getFilename` rows are read-only and immediate (`mc2::str::from_c`, `fmt::safe`, `_splitpath`, `strcpy`); each is re-read in the commit that changes the accessor and `tests/analyze/analyze_dangling.py --check` runs over every edited TU (the B1 lifetime gate).
- E5 An owned in-RAM image is a `std::vector<unsigned char>` member; the reads and writes keep using the pointer (`fileImage`), which becomes a view of it. A caller-owned buffer (`open(buffer,len)`) is a view only: closing never frees it. The two cases are told apart by whether the vector holds the image, not by `inRAM && (bFast || parent)`.
- E6 Parent/child (`open(File* parent, size)`, `addChild`, `removeChild`, `getParent`) is KEPT: a child is a view of its parent's handle, the child list is a `std::vector<File*>` of non-owning pointers, the parent's `close()` closes its children first (the order is pinned by a test before the change), and the contract is written at the declaration ("the parent outlives a read through the child"). The 18 + 3 census rows that use it stay as reviewed exceptions (`KEEP-child`); they are the census floor of game code.
- E7 No change on valid input. Malformed content gets an error code from the existing set and ONE log line, never `STOP`, an assert or an overrun (ruling 5): the packet header count must satisfy `0 <= numPackets` and `8 + 4*numPackets <= length`, and a fit file with no blocks opens (today it asserts on `Malloc(0)`). The 49-plus-character block id is NOT changed by B3: `test_file_inifile.cpp` pins its current handling (the STOP is logged, the name is kept as its first 49 characters, the next block still seeks), and replacing that with a rejection would change a pinned behaviour, which is the orchestrator's call. Every such change is listed in the commit message and in section 7b of this file when it lands (the B1/B2 practice).
- E8 `File::operator new/delete` and `ABLFile::operator new/delete` are deleted only in the LAST batch (B3.6), after the last `new` of the family in code that this lane may edit; `systemHeap` itself is B4. B3.1 replaces the `systemHeap->Malloc` calls INSIDE the classes with standard containers.
- E9 File formats, `elfHash`, FST/loose/mod resolution order and the `fst_normalize_*` calls of `File::open` are not edited: the opener keeps its exact sequence; only the type of the name changes (`fileName.data()` is passed where the `char*` was).
- E10 No static-duration owners: the dead traffic log goes (own commit, after the grep of the flag shows no setter). Comments say WHAT and WHY; CRLF kept (`git ls-files --eol`); readers log through `MC2_LOG_ONCE`/`MC2_LOG` with a census-registered tag; new standard headers in a header that a PCH-skip TU includes need the include-only commit first (D16: `file.h` is included by `move.cpp`, `group_goals.cpp` and others on `cmake/pch/pch_skip.cmake`).
- E11 Destructors and moves are `noexcept`; no new throw in a game loop; `std::bad_alloc` terminates (ownership plan section 12). The File family stays NON-copyable (`= delete`) so a copy cannot double-close a descriptor: today it is copyable by accident.
- E12 A batch that changes a header changes every includer the compiler reports in the same commit, including `data_tools/`, `tools/` and the editor targets that this lane does not own: `tools/build_all_targets.py` is the proof; an editor or tool file that needs a line changed for compile is a forced edit listed in the commit (the B2 `E-end` practice), never a refactor.

## 7. Hazards (each batch checks its own)
H1 child outlives parent's close: today the child keeps the freed name; E4 copies. H2 `close()` on a child calls `parent->removeChild(this)` while the parent's `close()` iterates `childList`: the vector must not reallocate or erase during that loop (the loop indexes, the removal nulls the slot, as today). H3 `inRAM` is set before the image allocation can fail (file.cpp:1459 sets `inRAM = FALSE` on failure only for the child-in-RAM case; the FastFile case reads into a null image). H4 `PacketFile::open(parent)` of a RAM child reads the packet into `fileImage` (file.cpp:1465): the vector must be sized before the read. H5 `File::open` normalises the name IN PLACE and reads it back in six later branches: the string must be final before any use (E9). H6 `eof()`/`getLength()` are used by the readers as the only bound; a size from a mod header is never trusted without `<= length` (E7). H7 `FitIniFile` objects are frequently kept as members of `Mission` (`gameSystemFile`, `missionFile`) and handed to dozens of `init(FitIniFile*)` functions as borrowed pointers (E3): B3.4 changes only the owner. H8 the ABL callbacks return the `File*` as `void*` through `**file = new File`; `ablFileCloseCB` deletes it: one factory pair, both in `code/ablmc2.cpp`. H9 multiplayer (`code/multplyr*`) is frozen: it has no census row.
