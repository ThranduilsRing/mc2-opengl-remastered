## Conversion decisions and review

- Objective, condition and action text owns `std::string` storage. Member
  accessors return `const std::string&`; setters take a string and move it.
  Localized labels and formatted descriptions return owned strings by value:
  unlike the runtime's constant species labels, the editor loads resources.
- C-string inputs from MFC/resource APIs use `mc2::str::from_c`. Literal
  formats use `std::format`; nullable display-name arguments use `fmt::safe`
  and formatted Boolean integers use `fmt::as_i32`.
- Existing EString equality used `Compare(..., true)`, which still fell back
  to Windows `lstrcmpi` when the bytes differed. Its objective snapshot text,
  flag IDs, action paths and messages therefore retain ASCII-insensitive
  equality with `iequals`. Species-token `strcmp` stays case-sensitive.
  This batch has no EString sort or index operations.
- The editor uses the existing `objective_text` optional readers, explicit
  Title fallback for missing Description, and numeric flag-ID fallback.
  `EditorData` text and the E-W authored model/coordinate preservation remain
  outside this batch. No wrapper, string-view member or static owner is added.
- Title and Description use the shared writer, preserving their previous
  CRLF-to-LF conversion. Fields formerly passed directly to `writeIdString`
  still use that raw writer with non-null `c_str()` values. This deliberately
  preserves their bytes, including multiline action text, under the newer E2
  instruction forbidding writer fixes. Applying the runtime writer's newline
  normalization to those fields would violate that instruction; C13's shared
  readers and non-null/always-write rules are retained without that change.
- MFC handler addresses in the edited dialogs are explicitly qualified.
  Two redundant private aliases in `EditorObjectMgr.h` are removed; the
  identical public aliases remain. Both were necessary for clang-cl to parse
  the edited TUs and change no handler mapping, storage type or layout.
- Reader sign-off: the MFC objective dialogs remain compile/lifetime checked,
  not instantiated headlessly. The smoke proves objective model persistence
  and existing workflow probes, not interactive dialog reach.

### Borrowed pointers (C8)

| Sites | Owner and lifetime |
|---|---|
| ObjectiveDlg readable condition/action text | Flag/path/message pointers refer to live condition/action members; no mutation, copy or relocation occurs before the same call formats an owned result. |
| ObjectiveDlg list and text-box updates | AddString and CString assignment consume/copy the local string or live objective member before its next mutation. |
| ObjectivesSummaryPanel labels/parameters | Computed description strings are local owners spanning the immediate ImGui calls; title/flag references refer to the live objective and never escape rendering. |
| TargetAreaDlg coordinates | SetWindowText copies each local formatted value before the next assignment. |
| FIT block names/species/writers | Local strings and optional values span immediate seek/map calls; writer pointers refer to live members for the synchronous write. No pointer is returned or retained. |

## Proposed commit

```text
refactor(editor): migrate B1.6 objective strings

Replace objective text ownership and 135 EString call sites.
Keep borrowed accessors tied to live members and use shared FIT readers.
Preserve the existing raw writer bytes; newline repairs stay separate.

Unlisted behaviour changes:
- Equality folds ASCII instead of the Windows locale; non-ASCII text
  and collation-ignorable characters may compare differently.
- Over-long FIT text is logged and ignored rather than truncated.
  The shared reader accepts exactly 2000 characters.
- Unset action text is empty in previews instead of CRT "(null)";
  unassigned string writes are defined empty values instead of crashes.
- Qualified MFC handlers and removal of duplicate private aliases
  change no behavior. Stock written FIT bytes remain unchanged.
```
