```python
from pathlib import Path
files = sorted(p for d in (Path("mclib"), Path("mclib/stuff"))
               for p in d.iterdir()
               if p.suffix.lower() in {".c", ".cpp", ".h", ".hpp", ".inl", ".rc"})
for p in files:
    print(p.as_posix(), len(p.read_text(encoding="utf-8", errors="replace").splitlines()))
print("TOTAL", len(files), sum(len(p.read_text(encoding="utf-8", errors="replace").splitlines())
                               for p in files))
```

**Caller column:** `C/U/I` = external call-bearing lines / external type-or-data-use lines / direct include sites. Counts exclude the audited file, include its paired header/implementation when applicable, and de-duplicate each caller file:line. Top three files rank C first; when C is zero they rank supporting U/I dependencies. Numbers beside caller citations are the counted sites in that file. The underlying searches use `rg --json -n`; Appendix A records the scanner. Headers with no callable API still get U/I counts.

C is a **lexical call-site candidate count**, not a runtime reachability claim or an exact resolved C++ call graph. It includes inactive branches; it omits unqualified member/virtual dispatch that cannot be assigned safely by grep, and some external forward declarations can look like calls. U records token dependencies, so common type names can collide. These limitations are explicit rather than silently reporting every `init()`/ `render()` in the repository as a caller. C=0 alone never licenses a deletion.
