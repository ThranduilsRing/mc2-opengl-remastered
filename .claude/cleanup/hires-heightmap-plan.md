# Global visual hi-res heightmap plan (read-only recon, 2026-10-09)

## 1. Existing cook pipeline
- `tools/terrain_beautify/visual_heightfield.py` writes `<m>.beauty/visual_height_4x.r32` (float32 V*V, V=(N-1)*F+1; 120^2 map -> 477, 910 KB), `visual_height_mips.r32` (max-mips for geomorph), `visual_damp.r32` (reauth only), `visual_height_report.json`. `upsample_corner_pinned` (:110) = bilinear. Modes: plain bilinear ("boring"), `--reshape` (:152), `--reauth` (:740; Taubin band-pass + tanh drift limit; CLIFF-SMOOTH-1 terrace melt; SHORE-CONTOUR-1 `shore_contour_reshape` :615 = marching-squares waterline -> arc-length Gaussian -> SDF (scipy EDT) -> tanh-bounded bank reshape, micro-puddle suppression). `--factor` arg exists (:1372); a 16x bake exists for mc2_17.
- `height_delta.r32` / `protected.r8` / `sidecar.json` are the GAMEPLAY-smoothing path (`mission_smooth.py`, `mission_sidecar.py` patches the .pak, baseHash-guarded), NOT the visual path. protected.r8 = 2 structural (road/runway/bridge overlay + building footprints, 1-ring dilated), 1 water, 0 editable (`mission_smooth.py:154-158`). Only mc2_01 and mc2_24 have them (tests/terrain/beautify/*.beauty).
- Visual bakes: all 24 maps have `tests/terrain/beautify/mc2_NN.beauty/visual_height_4x.r32`. Only mc2_01, mc2_17, mc2_24 are `--reauth`; the other 21 incl. **mc2_10 are plain bilinear** (zero new information). No bake used the shore reshape (report `shore: null` even on mc2_17). Deploy: `data/missions/<stem>.beauty/` (loader `mclib/terrain.cpp:1270,1359`).
- Gaea: `tools/terrain_gen/import_gaea_height.py` (r32 -> new .pak/map; fix 077526e3). Gaea would plug in as a replacement `visual_height_Fx.r32` (same file/format) or as a new map's gameplay height.

## 2. Does rendered terrain use it?
Yes, but **default OFF**: env `MC2_TERRAIN_VISUAL_DISPLACE` (loader gate `mclib/terrain_init.cpp:717`; registry RenderCore/RendererFeatureRegistry.h:3474). `terrain_lod_chunk.vert:152` mode 1 = LOD0 near band on a 4x-finer chunk grid (hardcoded `*4`, `>>2`, `0.25` at :110,157,164 and V=(N-1)*4+1 in mclib/terrain_init.cpp:720); mode 2 (:295) = coarser bands sampling max-mips + geomorph. Damp (binding 27) blends toward coarse near buildings/movers. Not tessellation: `MC2_TERRAIN_CLIFF_DISPLACE` (GameOS/gameos/gos_terrain_lod_chunk_internal.h:190) is a pass-through TCS/TES spike, no displacement. Water mode 2/3 samples the sidecar (shore only). VK: `vulkan_terrain_island.cpp` snapshots the SSBO (:2034) but honors only visualMode 0/2 (:2640) = far-band; no near-field 4x mode 1 in VK (verify). Water VK port of mode 3 pending.

## 3. Gameplay and grounding
Gameplay height = `MapData::blocks[].elevation` via `Terrain::getTerrainElevation` (terrain.cpp:4498); TerrainRuntime (mclib/terrain_runtime.h:45-48) keeps `sampleGameplayHeight` vs `sampleVisualHeight` distinct; grounding chokepoint `groundElevation`, ~47 sites. A visual-only sidecar cannot change pathing/LOS/projectiles. Visual-vs-gameplay mismatch is ALREADY handled in-shader by the damp map: building footprints (static, radius 256wu) and live movers (`code/mission.cpp:1262-1300`, radius 256, `UpdateVisualDampMovers`) force damp=0 -> the mesh reverts to coarse Z under them. So units/buildings do not need snapping; cost is a visible local "bulge/dimple" ring around moving units. Props/trees (non-mover, non-footprint) are NOT damped: the veg adapter and decals are the exposed consumers (obj5 vegetation was reverted; decals via `decalElevation`->visual, gate MC2_TERRAIN_RUNTIME_DECALS). Safe delta without grounding work: roughly <=3-6 wu (~unit foot/decal offset); the stock bake peaks at 190-660 wu delta (mc2_10 max 191, mean 7.8), so a global bake needs a clamp or grounding migration. Unit-float check: log max |visual-gameplay| at each mover position.

## 4. Why prior attempts "didn't help"
1. Plain bilinear 4x adds no information: shore/terraces remain (staircase index mc2_10 0.737; SHORELINE-V0-FALSIFY-1). 2. Corner-pinned stock displacement was invisible by math (mean 5.9 wu; terrain-v2-arc memory). 3. Displacement gate default OFF and VK lacks near-field. 4. Waterline is set by the 128 wu mesh/water-plane intersection; mode 2 only min()s. 5. Failed fixes derived only from coarse data (B-spline residual NO-GO: reach 5-6 wu).

## 5. Proposed plan
Cook (new `bake_global_visual.py`, extend visual_heightfield; ~1-2 d):
- F=8 (V=953, 3.6 MB/map; 24 maps ~87 MB; mips ~ +0.3 MB). 16x only if 8x proves insufficient (14.5 MB/map).
- Upsample: bicubic/Catmull-Rom (C1) of coarse, NOT bilinear; corner-UNpinned per owner ruling.
- Terrace-aware smoothing: detect risers (one-sided step, `coarse_cliff_mask`/`onesided_step`), keep intentional cliffs (slope > ~45 deg and step > ~80 wu, regional extrema), melt terrace treads (existing CLIFF-SMOOTH-1 melt + Taubin), drift tanh-bounded by field: flats 24 wu, risers up to ~40-60 wu (NOT 112).
- Protected: overlay + footprints (+1 ring) feather-pinned to bilinear baseline (reuse `protect` in reauth; also union protected.r8 where present).
- Coastline: SDF of waterline from the smoothed field (existing `shore_contour_reshape`; sigma 3.5 coarse cells, band +/-1.5 cells = +/-192 wu, bank slope clamp 0.08-0.8, max adjust 64). Run AFTER terrace melt, band excluded from detail noise.
- Global clamp |visual - bilinear| <= 40 wu (report p99), emit `visual_damp.r32`, mips, report.
Render (~3-5 d GL, +3-5 d VK):
- Parameterize factor (uniform `u_visualFactor`, replace hardcoded 4 in shader + terrain.cpp V calc + mips/stride tables); near LOD0 band at 8x = 16 wu grid: 64x tris per block vs 16x now -> cap by distance (only blocks within near radius; LOD1 at 4x via stride). Budget: measure Terrain Tracy zone; target <=+0.5 ms.
- Terrain and water must share one field: water mode 3 already uses Catmull-Rom of the sidecar; make both read the same bake (same F); terrain near-shore gets LOD0 forced so mesh crosses water plane on the SDF curve (a denser shore chunk list, cheaper than tessellation). Tessellation spike is the fallback for far shores.
- VK: add mode 1 (near fine grid) to the VK terrain pipeline + water mode 3 port.
- Splat/texture: colormap and control are already 5120^2/world-space UV (independent of mesh); normals should come from the hi-res field (NFH normal tex via visual height, "shading-only" option) to avoid faceted lighting. No splat change needed.
Verification: `terrain_workbench.py` offline (blockiness, protected, footprint checks), top-down full-zoom captures mc2_10 off/on + gameplay-angle captures, `run_visual_capture.py`; unit-float oracle (log mover/prop |dz|); gate-OFF byte-identical; tier1 smoke.
