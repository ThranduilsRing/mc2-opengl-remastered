Read-only review. Nothing built, launched or committed. ## Verdict
Memory-safe design; barriers, std140/std430 layouts and the Slang ports match the GL shaders. One real functional bug (descriptor binding 6 is permanently the native thin buffer, so the old feed draws the wrong buffer on any frame that does not run native), plus a periodic release stall and a record failure that kills water instead of degrading. Fix the must-fix before declaring 3.4P default-on. Lighting is proven only by the synthetic self-test and cull/pack only by sampled parity frames.

## Must-fix
1. Old-feed fallback draws the wrong buffer once native is ready. `write_descriptors` (vulkan_water_island.cpp:151) points binding 6 at `native->thin(i)` whenever `native->ready()`. A frame can still take the old feed while native is ready: `MC2_WATER_GPU_FULL_RECIPE_AUTHORITATIVE=0` (the documented opt-out; native capture sits inside `if (fullRecipeAuth)` in gos_terrain_water_stream.cpp ~1585-1606), or `nmvp == nullptr` falling through the `nativeMode==1` return. Then run.cpp (`!nat`) copies the GL records into `s->thinBuf[par]` and calls `vkCmdDraw(thinCount*6)`, but the vertex stage reads the native `thin_` (stale or never-written device memory). Fix: on `!nat` with native ready, rewrite binding 6 of slot `par` to `thinBuf[par]` (slot is retired then), or make `mc2_vk_water_native_mode()` return 0 when full-recipe-auth is off, and stop `write_descriptors` switching on `ready()` alone. Add a check for the opt-out.

## Should-fix
1. Periodic release stall. Parity frames (native frames 60, 600, then every 3600th) run in shipped default-on code: `waitIdle`, a GL `glGetBufferSubData` of the lighting window, `ReadbackGpuThinForVk`, and the GL cull dispatch. That is a full stall about once a minute at 60 fps, forever. Keep 60/600; put the periodic ones behind a diag env, or raise the period to ~100k.
2. `native->record` failure disables the whole water island (`setFallback("native_record_failed"); s->disabled = true`) instead of degrading to the old feed, and returns with the command buffer already begun and never submitted. Every `return false` in `record()` happens before any command is recorded, so stage inputs (grow, uploads, UBOs) before `vkBeginCommandBuffer` and take the old feed for that frame (needs must-fix 1). Init failure is already fail-soft (`nativeFailed`); record failure should match.
3. Overflow is silent. `maxThin_ = min(recipeCount, 131072)` shows only in the "ready" line; a clamp that bites is visible only on a parity frame. The draw is safe (see Checked-OK) but water is dropped. Warn at init when `recipeCount > kMaxThin` (map side above ~362 vertices) and check the large mod maps.
4. Self-test result is ignored: `selfTestLighting()` returns the mismatch count but `init` sets `ready_ = true` regardless. A driver whose FMA contraction differs would log a mismatch and still ship the lighting. Either clear `ready_` on mismatch (falls back to the GL feed) or document it as advisory. The test also fixes `rendererSW=0, useFog=1, rain<1, lightening>0` and so never exercises the other branches, and its reference is a transcription by the same author, not GL output.
5. Parity truncation gives false-red lines: `compare()` caps VK at `kParityCap` (32768, atomic order) but compares the full GL list, inflating `only_gl`. Truncate both sides by recipe index or print only `truncated`.
6. Proof gaps to record as unproven in the state file: no Tracy run (no data on the barrier cost, the ~1.3 MB per-frame window memcpy to host-visible memory, or the readback saving); live lighting values over a real window never compared to GL (the live window was empty); cull/pack parity is sampled at frames 60/600 only.

## Checked-OK
- Barriers. Start of record: ALL_COMMANDS / {SHADER_WRITE, TRANSFER_WRITE} to COMPUTE|TRANSFER covers cross-frame WAW/WAR on the shared `lightOut_`, header and the previous cull read. Fills to compute RW: correct. Lighting to cull, cull to args: COMPUTE WRITE to COMPUTE READ, correct. Final: COMPUTE WRITE to VERTEX_SHADER|DRAW_INDIRECT with SHADER_READ|INDIRECT_COMMAND_READ, correct (plus TRANSFER_READ on parity). Parity: TRANSFER_WRITE to HOST_READ, then waitIdle. All stage/access pairs are legal, no image layouts involved, buffer usage flags match (lightOut TRANSFER_DST for the fill, drawArgs INDIRECT_BUFFER, header TRANSFER_SRC), firstInstance=0 so no drawIndirectFirstInstance feature, stride 16. No validation hazards found by inspection.
- Descriptor lifetime: per-slot sets (kSlots=2), rewritten only after `growHost` idled the device or at init; `writeAll()` rewrites both slots with nothing pending. Single queue: shared `lightOut_` is ordered by the in-queue barrier, so even two frames in flight are safe for shared buffers; per-slot buffers are fence-retired; parity buffers are shared but a parity frame waitIdles.
- Thin capacity: the cull's atomic counts past the cap but writes are guarded by `outSlot >= maxThin`; `water_draw_args` clamps `min(header[0], maxThin) * 6`; `thin_` is sized `maxThin*48`. No OOB read or write on overflow, water is only dropped.
- Teardown: `native` is declared last in `WaterIsland`, so it is released before `recipeBuf` (which its sets reference) and the island pools. Inside `NativeProducers` buffers are declared after sets and pipelines, so release order is buffers, then sets, then pipelines (module, layouts); device idled before island retire. Recipes are mission-static and the island is retired on resize or mission change, so `recipes_` cannot dangle.
- Slang vs GL. Lighting: math, 0xAARRGGBB packing, shadow clamp, fog and haze branches, play-area test and integer truncation are identical to gos_terrain_lighting.comp. Input indexing differs by design (Slang `vertices[id]` over the snapshot window, `vn = id + vertexOffset`, output by absolute `vn`; GL indexes absolutely) and is consistent with `VkProducerSnapshot` (window points at `packMinVN`). Cull/pack: eligibility predicate, byte unpack of waterBits and terrainTypes, both `pzOk` bias modes, tri1/tri2 per UV mode, vn0..3 = quadIdx, +1, +ms+1, +ms, material in the fog low byte, 48 B record, flag bits all match. Sentinel: `lightOut_` filled 0xFFFFFFFF once (and again after the self-test dirties it), as the GL SSBO clear; vertices outside the window keep it in both backends. Struct sizes (32/48/8/64/48) and std140 UBOs (128/96/16) have static_asserts and match the Slang field order.
- Draw args = {min(count,maxThin)*6, 1, 0, 0}; header zeroed by `vkCmdFillBuffer` before the cull each frame.
- Parity cost when off: no extra GPU copies, readbacks, waitIdle or buffers (created on first parity frame); only the mode query (twice a frame) and the ~150 B snapshot fill and copy.
- s52 changes (single parse rule, typo to Vulkan with logged coercion, canary and interop gates removed) are consistent with the updated tests and baselines.
