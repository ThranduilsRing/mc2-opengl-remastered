## Must-fix
1. Unrecognized MC2_RENDER_BACKEND disagrees across three readers.
   - `render_backend_select.cpp` resolveOnce() still ends with "unrecognized ... coercing to GL" and returns GL.
   - `render_backend_select.h` now documents "unrecognized -> Vulkan".
   - `mclib/vk_umbrella_gate.cpp` umbrellaOn() treats only exactly "gl"/"GL" as off.
   - `scripts/smoke_lib/capture_backend.py` requested() maps every non-gl value to Vulkan.
   Result: a typo (`opengl`, `Vulkan`, `Gl`) gives a GL present with the VK umbrella ON, so every VK-owned layer vanishes (the torn-scene signature the old DISARM flag prevented), and the capture mismatch check reports "requested vulkan".
   Pick one rule. Smallest: resolveOnce() returns Vulkan for unrecognized (log "coercing to Vulkan"). Better: umbrellaOn() calls `mc2::renderBackend()` instead of re-parsing the string; this removes the duplicate parser and the per-call std::string read (the backend is now immutable after first resolve).
2. The GL arms of the tools were not given an explicit arm (plan 3.2 required it). Unset now means Vulkan:
   - `tools/visual_verify/ab.py` main(): the GL arm runs `run_capture(..., [])`, so the compare is VK vs VK and passes capture_backend (requested=vulkan, drew=vulkan). Needs `MC2_RENDER_BACKEND=gl`.
   - `tools/visual_verify/capture_ab.py` capture_cmd(vulkan=False) adds no backend env, and `test_capture_ab.py::test_the_vulkan_arm_asks_for_the_shared_gbuffer_umbrella` asserts the GL cmd has NO MC2_RENDER_BACKEND, which locks in the wrong behaviour.
   - `tools/visual_verify/bless.py` BACKEND_DECLARED_ENV["gl"] = {} (refuses loudly because requested != "gl", so safe but unusable).
   Check any other GL arm in tools/ that relies on unset.
