## Tool notes (new this session)
- Deploying from a fresh worktree (the probe exe) rewrites tracked data files with their committed (LF) bytes: `data/tgl/QuonsetGLB.mcasset.json` is 2642 bytes there against 2701 in this working copy, and the data fingerprint is path + size, so every baseline check then fails on the fingerprint. After such a deploy copy the file back (`cp -p data/tgl/QuonsetGLB.mcasset.json <install>/data/tgl/`) or deploy from main.
- objhash over every target: `build-alltargets` is the all-targets Ninja tree (`tools/build_all_targets.py --root-only`); take the sources from its `compile_commands.json`, call `objhash.hash_files(..., per_symbol=True)` from Python (a command line of 1000 paths is too long), compare after the edit. "object not rebuilt" in the compare means no input changed. Fingerprint-embedding TUs differ by the sha: build the "before" and "after" objects with `MC2_FINGERPRINT_FREEZE=1` (run ninja under vcvars via `configure_ninja.under_vcvars`), or compare symbol names by hand with `objhash.symbol_table`.
- `git stash push` with a pathspec fails on staged deletions; stash everything tracked (`git stash push`), build, `git stash pop`. A scratch object compile needs the tree's PCH to match the sources, so rebuild in the tree instead of compiling by hand.
- `tests/callers.json` also lists scripts under `tests/analyze/` that import `console_child`; regenerate with `py -3 tools/callers.py` after adding one.
- Scratch worktree for old exes: `git worktree add --detach A:/Games/mc2-g2 <sha>`, apply `tests/analyze/b2_probes/apply_probes.py A:/Games/mc2-g2`, commit there (clean tree = fingerprint matches the worktree HEAD), `py -3 scripts/ninja_build.py`, `py -3 scripts/deploy_payload.py --target game --ninja`, run `py -3 tools/sim_determinism.py check <mission> --out DIR` FROM that worktree, then `py -3 tests/analyze/b2_probes/summarize_probes.py --window 1000 NAME=LOG...`. Redeploy main afterwards.
