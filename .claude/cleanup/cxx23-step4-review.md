## Findings → plan edits
1. **Game objects row is the wrong model**: objects are per-type POOLS allocated at mission load (objmgr.cpp:255-386), recycled never freed mid-mission (createWeaponBolt reinitialises a free slot, objmgr_misc.cpp:449), deleted per type in destroy() (objmgr.cpp:934); handle = objList index and watchIDs are SAVED (gameobj.h:271); generational handles already exist (objmgr.h:256; objmgr_contract_harness has 20 generation refs). Rewrite: manager owns fixed per-type pools; slot order + handle = slot index are part of the save format; B7 extends the harness to slot reuse.
2. **Save format = in-memory struct layout**: Load dispatches on packetSize == sizeof(XData) (objmgr_io.cpp:761-1050), no static_asserts; STOP is a no-op in RelWithDebInfo (objmgr_misc.cpp:459) so a size mismatch leaves null slots → the stale-save crash at objmgr_io.cpp:1143 [unverified]. Add a row: freeze sizeof/offsetof of every *Data struct (+ pairwise distinct sizes) before any batch; count STOPs → reject-and-log (ruling 5).
3. **ABL row keeps a facade**: allocation goes through host callbacks (ABLi_init code/ablmc2.cpp:295 sets ABL*MallocCallback, mclib/ablrtn.cpp:378-381). Delete the callbacks: stack = std::vector<StackItem>, each ABLModule owns its staticData, one pmr resource per module for symbols/code. Module INSTANCES have two ownership modes: after quickload ABLi_loadEnvironment news them (ablenv.cpp:1544) held only by the non-owning ModuleInstanceRegistry and later deleted by warriors/mission (warrior.cpp:1035, mission.cpp:642); on a fresh start the same fields own a new ABLModule (warrior.cpp:1296, mission_init.cpp:958). Environment owns every instance; brains are non-owning handles. The arena (symbol/code memory) is NOT in the save format and need not wait; instance ownership/order must (registry swap-remove ablenv.cpp:1423 makes destruction order decide saved order). Save stores: library/module names, instance positions (getRealId = registry position, ablenv.cpp:461), state names, initCalled, static/eternal variable bytes, raw sizeof(StackItem) union bytes (ablenv.cpp:1452-1475, 575-600).
4. **gosFX row wrong owner**: mc2::particles::SpecLibrary owns specs (effectlibrary.cpp:17-21), EffectLibrary forwards; Effect::Make is a plain new (effect.cpp:503) → plain unique_ptr<Effect>; children freed in two places (DeletePlugs in ~Effect effect.cpp:483 and the Kill path); specs hold MLRShape intrusive refcounts (shape.cpp:132-213, debriscloud.cpp:66,170) → B8 keeps Attach/DetachReference even with MLR out of scope.
5. **AppearanceType/TG cache**: "load once" silently drops the numUsers refcount unload (apprtype.cpp:300-508); two hosts create/delete the global appearanceTypeList (game mission2.cpp:121 / mission.cpp:813; editor EditorObjectMgr.cpp:84 / _render.cpp:266). State the refcount decision; owner = Mission or editor document, not a global.
6. **Textures missing**: refcounted handle indices (numUsers txmmgr.h:160) released via two APIs (removeTexture / removeTextureNode) from 30 sites incl. mlr/gosimage.cpp → add a row (move-only TextureRef).
7. **§7 "both are malloc, nothing observable changes" is false**: AppearanceType::operator new returns null when the heap is not ready (UB; apprtype.cpp:72-80) and its delete skips the free after teardown; UserHeap::Malloc returns null when uninitialised (heap.cpp:353-365); 9 heapReady() guards (collsn 5, apprtype 2, appear 2) contradict audit C4. Heap teardown frees NOTHING today (gos_DestroyMemoryHeap gameos.cpp:198; objectCache "reclaimed with the cache" objmgr.cpp:246) → migration turns "reclaimed with the heap" into destructors that never ran: the risk is use-after-free / teardown order, not leaks.
