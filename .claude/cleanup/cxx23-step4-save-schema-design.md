# S3 / B7: one value schema for exact mission resume
Replace memory-image saves directly; retain a fixture-only legacy reader, then delete it.
Design only, grounded at worktree HEAD `8300da27d` (2026-10-13); final-release schema freezes with that release line.

## Contract and decisions

The owner permits pre-release save breaks, requires simulation determinism, and prioritises every editor workflow, cinematics and in-mission videos. Architecture section 2.6 supersedes the ownership plan's optional packet-after-END proposal and the fidelity report's minimal extension: there is one new writer, no appended compatibility payload and no permanent dual format.
Exact resume means identical authoritative state at the saved completed tick and identical continuation for the same subsequent TacticalOrder envelopes at fixed 30 Hz. S1 must first remove camera-dependent sim scheduling and provide the complete digest. Today's fixed timestep is a smoke mode (`code/mission_update.cpp:300`), while production uses wall-clock deltas (`code/mission_update.cpp:320`).
Save at a committed tick boundary: ABL calls and path solves have returned, damage/orders for that tick have committed, and no worker can mutate the snapshot. Requests still awaiting execution remain state. UI save requests wait for this boundary; arbitrary interpreter stack capture is unnecessary under this contract.
`MissionState` owns the snapshot and restored world. ObjectManager owns fixed per-type pools; every observer uses an ID. No static-duration owner, address-keyed order, per-object owning pointer list or C++ ABI enters the format. Multiplayer remains the named compiled-out exception.
The single [shared sim/save contract](sim-kernel-design.md#shared-simsave-contract) defines owners, clocks, stream IDs, ingress, ABL, media, Environment and editor lifecycle; this document defines their wire records, not a second contract table. Speed means ticks per wall second and belongs to presentation; pause/speed/wall credit never enter authoritative state.

## Wire schema, defined once

Implement one C++23 `void T::serialize(Archive& a)` per row below. Its body is exactly `a(field1, field2, ...)` in the listed order; nested rows invoke their own function. Reader and writer Archives share these functions, fixed scalar codecs and validation metadata. Never maintain separate Save/Load field lists, dump a struct/union/StackItem, dispatch on `sizeof`, or serialize a pointer, vptr, native handle, padding, unused capacity or allocator state.
All integers use explicit widths, little endian: IDs/counts u32 (signed sentinel-bearing IDs i32), other source signed/unsigned integral values i32/u32, ticks/call counters u64, generations u32, documented bounded byte fields u8/i8, cell coordinates i16. Freeze enum/tag numeric values in the schema, independent of C++ enum ordering; unknown values reject. Floats use IEEE binary32 bit patterns, doubles binary64; preserve signed zero and valid sentinels, reject non-finite gameplay values. Vectors serialize components, never their native layout.
Sequences have u32 length and element codecs; validate length against schema caps, mission dimensions and total decoded-byte budget before allocation. `[n]` means exactly n elements; `[count]` means only the live prefix. Paused paths use `numStepsWhenNotPaused`, not `numSteps`, for their stored prefix. Counts equal sequence lengths; validate cursor/sentinel bounds separately. Inactive variant arms have no payload. No sequence reorder unless its semantics are unordered; pools, rosters, queues, contacts and ABL registries retain their exact order.
Text is `{encoding:u8, bytes:length-prefixed}` with supported UTF-8 and legacy Windows-1252 encodings; validate encoding without locale conversion and preserve bytes/newlines. Asset keys are bounded VFS-relative text, never machine absolute paths. IDs resolve within the snapshot; null is an explicit optional value, never a magic address. A save object reference is `{slot:u32, generation:u32}`; watch-ID mapping remains a separate table because watchID is not necessarily the object slot.
Fields named WID retain their numeric watch IDs and resolve through the validated WatchEntry table; ObjectRef fields carry the slot/generation pair. Pilot/module/request IDs use distinct typed domains. Concrete object tags are 1 GameObject, 2 Mover, 3 Mech, 4 GroundVehicle, 5 TerrainObject, 6 Building, 7 Turret, 8 Gate, 9 Artillery, 10 Carnage, 11 WeaponBolt; reserve 12/13 for live light/elemental types only after the B7.0 census. Encoding tags are 1 UTF-8, 2 Windows-1252; RNG algorithm tag 1 is today's LCG15, version 1, exactly one u32 state word.
LCG15 is explicitly `state = state * 1664525 + 1013904223` modulo 2^32, output `(state >> 17) & 0x7fff` (`mclib/det_rng.h:21`); stream-specific bounded-roll shaping stays outside this state transition and is release-bound. This fixes the algorithm contract independently of compiler/CRT implementation.

## Validation and restore transaction

Bound the whole file, sections, decompression if later added, strings and nested arrays; reject duplicate/missing required tags, unsupported versions/release lines, bad hashes, unknown required sections, invalid enum arms, ID collisions, wrong reference types, impossible dimensions/counts/cursors and content-fingerprint mismatch. Optional unknown presentation sections may be skipped only when marked optional; required sim state never defaults. Header build SHA is provenance, not the compatibility discriminator.
Decode into an owned snapshot, validate references and content requirements before replacing the running mission. Instantiate resources/types and ABL definitions, then slots/instances, then values, watch/brain/path/sensor links and schedules. Rebuild only declared derived caches. Publish the complete restored MissionState atomically; no tick, ABL init, random draw, sensor scan or path request may run during hydration. Allocation/load failure destroys the staged state and keeps the old world usable.
Every rejected file produces one diagnostic such as `[SAVE v1] reject reason=... section=...`; return a recoverable error, never STOP/Assert/ABL_Fatal on file-controlled content. Unsupported current v0.4/retail saves use the same rejection contract. Write to a sibling temporary file and atomically replace only after serialization/hash completion; no partially written save replaces a usable save.
For byte identity preserve originBuildSha and releaseLine from the loaded header; write current runtime build provenance to the log. No wall timestamp, fresh UUID or load count enters the file. Canonical version-1 output is uncompressed initially, avoiding compression-version noise. Validate SHA/length before consuming any section, and test rejection leaves the prior mission intact.

## Risks and unresolved engineering checks

- Snapshot completeness is the largest risk: legacy Data structs omit process schedulers, contact queues, brain latches and pool cursors. An old digest or semantic equality that ignores them can falsely pass; complete census/digest mutation and full continuation are mandatory.
- ABL declaration-driven codecs must distinguish scalar/array storage and references; union-sized StackItem reads can carry addresses or uninitialised upper bytes. No VM memory blob is accepted. Validate compiled symbol fingerprints before linking callbacks.
- Legacy fixtures cannot invent lost state; the noise mask expressly hides large pilot path ranges and most CommanderData. Keep it out of new-format assertions. Existing save_inspect RECORD_SIZES (`tools/save_inspect.py:37`) identifies only the current ABI, not schema tags.
- Old initialization mutates restored appearance/brain state; hydration must not call gameplay initialization twice. Pool teardown exposes frees the old heaps never performed; staged-load rollback and ASan reload are essential.
- Path/collision/search caches can retain history; synchronous safe boundaries must be demonstrated, and reconstruction must preserve tie/order and cost bits. Light/elemental pools, radio policy and mission end transitions need the B7.0 reachability/census proof before excluding any state.
- Portability requires fixed wire widths, explicit text encoding and floating arithmetic parity; a portable file alone does not prove cross-platform bit-identical sim. Content fingerprinting must cover resolved mod/VFS order, scripts, CSV/FIT/PAK and animation assets, not only filenames.
- Effective sim options are saved as SimRules/fingerprinted and restored before any tick; unsupported IDs reject. Renderer settings cannot invalidate a sim save or advance its RNG. Appearance/RenderWeather checks are separate from authoritative Environment and its required RNG. Safe rejection needs caps sized for supported mods, not stock-only guesses.
- Editor MOVE packets share existing writer entry points; runtime schema deletion must preserve mission/content codecs. One final release waits for full migration, Vulkan and editor workflow closure; interim broken saves are allowed, broken mod content is not.

Shared owner ruling: ABL camera getters return the last scripted camera value, retained by the wire records. Stock mc2_01, mc2_10 and tut_01 save and restore the camera around cutscenes; mc2_01's mid-mission read now restores the scripted rotation, an accepted difference. Live player-camera reads stay banned. All other listed checks affect implementation readiness, not owner intent.
