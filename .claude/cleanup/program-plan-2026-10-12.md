## 4. Operating protocol for fewer, bigger agents

- **Checkpoint cadence**: a lane refreshes its state file and appends one `verified` line (`sha build doctest board tier captures`) at every commit batch, at most every 2 h; the orchestrator reads only state files and `git log`, never the transcript. The 6 h cap stays; the second session of a 10 h task starts from the state file. Hard stop at 6 h even mid-batch (commit or revert, never leave edits).
- **What replaces the Opus review**: (1) mechanical, tool-proved steps (2, 3, amnesty): a fixed self-review checklist in the task's exit report (proof mode per commit, every accepted-not-identical object named, ratchets only down, ledger complete, no never-touch file, no proof default changed) plus an orchestrator spot-check of three random commits re-proved with the tool; (2) design steps (every step 4 batch): a separate read-only Fable reviewer (R1, R2) per two batches with the step 4 checklist — free-site inventory diff, teardown order written, no new throw in game loops, no static-duration owner, pointer-ordering scan clean, SIMID + save baselines unchanged, build_all_targets + editor smoke, portability seams (no HANDLE/COM/SEH), multiplayer untouched — verdict ACCEPT / ACCEPT-WITH-FIX / REJECT, findings routed to the lane before its next batch; (3) a lane never reviews its own design batch; (4) the Fable meta-review runs once per week (M), reads only the state files, the log, `verified` lines and the diffs it samples, and writes next week's plan.
- **Orchestrator vs lane**: orchestrator = merges (`lane_merge.py`), capture viewing, handoff/log, owner questions, lease schedule, budget ledger, archive of stale docs, spot-checks; lane = everything inside its brief including every proof and the state file; a failing proof is reported and that batch stops, the lane continues with the next independent item; a lane never changes a proof standard, default or baseline rule (it rewrites a ratchet baseline only with the reason in the commit).
- **Budget ledger**: the orchestrator records Fable percent used after each task in the log; if T1 + T2 exceed 35 percent, T6/T7 are cut; if any task passes 15 percent without its first exit criterion, it is stopped at the next commit and re-briefed smaller.
- **Every brief** ends with the efficiency retrospective; the orchestrator folds accepted items into the tool backlog line of section 1.
