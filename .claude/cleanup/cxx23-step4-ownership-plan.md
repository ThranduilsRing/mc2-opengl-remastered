# C++23 step 4: ownership, designed as we would write it today (PLAN ONLY, nothing edited; for the Opus design review)

Lens (owner): not "wrap today's pointer flows in unique_ptr". Per subsystem: (a) the ownership model we would choose, (b) the path there, (c) what legacy shape must stay and why. Hard constraints are only on-disk/binary formats, gameplay determinism and mod CONTENT. In-repo tools (mc2fx, asset_viewer, mech_import, tg_import_dump, launcher, data_tools) are rebuilt against the new API in the batch that changes it (`tools/build_all_targets.py` is the proof). Anything that would break an EXTERNAL tool we do not build is a decision point (section 9), not a design input.

Patterns: (P1) owned member pointers freed in destructors or `destroy()` (UI widgets aObject/aText/aRect/aAnimation, ~150); (P2) list items handed to a container that deletes them (aTextListItem 36, MechListBoxItem 8, ...); (P3) factories that allocate in one place and are freed by a registry elsewhere (ClassData 61, AppearanceType 4, TG_TypeMultiShape 27, MLRShape 22 + AttachReference/DetachReference); (P4) `new T[n]` + a separate length field (char 83, Point3D 45, unsigned char 41, Vector2DScalar 26, RGBAColor 13); (P5) files and streams (`new File` 29, FitIniFile 17, PacketFile 6, ABLFile 6, MemoryStream); (P6) per-subsystem arenas: 28 UserHeap/HeapManager, class operator new routing to `systemHeap`/`objectCache`; (P7) intrusive and bespoke containers (DynamicArrayOf 40, SortList, PriorityQueue, EList, Stuff chains); (P8) game objects (GameObject family via `ObjectTypeManager::objectCache`, setExists(false) only in `destroy_instr`).
Facts that shape the design: the shipped heap IS malloc (`USE_GOS_HEAP` always defined; `gos_Malloc`=malloc; global `operator new` = gos_Malloc; `gos_DestroyMemoryHeap` frees nothing outstanding), so no heap has arena semantics today. There is no DLL boundary: every engine target is a static library; the only DLL is the string resource `mc2res_64.dll` (no allocations cross it) plus delay-loaded FFmpeg (C API, own allocator). Standalone tools each define their own `systemHeap`/stubs, one process per tool.

## 2. Ownership model per subsystem (what we would write today)
| subsystem | model | path from today | legacy shape that stays, and why |
|---|---|---|---|
| EString | `std::string` value; borrowed text is `std::string_view`; `Format` = `std::format` | add `EString::str()` view, convert callers file by file (code 46, editor 16, gui 7, mclib 3), then delete the class; owner ruling: migrate WITH the gui widgets | none on disk (resource strings are loaded into it, not stored in it); non-atomic COW refcount disappears |
| EList | `std::vector<T>` by default; `std::list`/`std::deque` only where a site holds iterators across insertion | per site (52 files): record the iteration/insertion contract in the batch note, convert, doctest the contract | insertion order and tie order decide gameplay (target pick, order queues): the container changes, the order does not |
| mclib value containers (DynamicArrayOf, SortList, PriorityQueue, BitFlag, MemoryBlock) | `std::vector`, `std::priority_queue`/sorted vector, `std::vector<bool>`/bitset; no placement new | leaf-first; PriorityQueue and SortList only with a tie-order oracle (pathfinding, move_*) | `pqueue`, `sortlist` tie order = movement outcomes (audit E): stable ordering is part of the contract |
| File / FitIniFile / PacketFile / ABLFile | scope-bound values (`File f; f.open(...)`) or `unique_ptr` returned by a factory (`openFit(path)`); never a raw pointer passed around | ~60 `new File`-family sites: most are open-read-close in one function | FST/.pak/.fit formats and `elfHash` untouched (mods and data_tools write them) |
| MemoryStream / gosFX streams | read side `std::span<const std::byte>` + a bounds-checked cursor value (`ByteReader`); write side `std::vector<std::byte>` (DynamicMemoryStream) | replace constructor taking `void*,size_t`; callers pass spans; MemoryStream class stays as a thin shim until the last gosFX loader moves | the `.fx` byte layout and the `RegisteredClass`/ClassID numbering are MOD CONTENT and stay exactly |
| UserHeap / HeapManager / class operator new | DELETE, no facade: ownership moves to typed owners (vector, unique_ptr, the owning subsystem object); lifetime-grouped data (mission) is owned by a `MissionData` object, not a heap | per heap (28): list its allocations, give each an owner, delete the heap; class-level `operator new/delete` (225 lines) deleted after the class moves, behaviour identical (they are malloc) | `HeapManager` (VirtualAlloc) only in bitflag.cpp; nothing relies on addresses, except places that sort or hash by pointer: scan for `map<T*` / pointer compare in section 7 |
| TG shapes, AppearanceType, ClassData (shared immutable assets) | a cache object owns them (`unordered_map<name, unique_ptr<T>>`, load once); users hold non-owning `const T*`/handles; the registry is the single owner | the cache already exists in spirit (`AppearanceTypeList`, `ObjectTypeManager`); make its ownership explicit and remove the second `delete` sites | asset names and load order (mission data); TG_GOSVertexPool slab stays: it is a measured per-frame pool, a legitimate arena with its own owner type |
| UI widgets (aObject/aText/aRect/aAnimation, list items) | widgets are members (values) of their screen or `std::vector<std::unique_ptr<...>>`; list boxes OWN their items (`add(std::unique_ptr<Item>)`); `destroy()` becomes the destructor | per screen (pilotreviewarea, mechlopedia, objective, salvagemecharea, mechlab...), with EString to std::string in the same diff | `.fit` UI layout files and localized string ids are content: the loader reads the same keys |
| game objects (Mech, GroundVehicle, Building, Turret, ...) | `ObjectManager` owns every object (`std::vector<std::unique_ptr<GameObject>>` + stable handles); types are owned by `ObjectTypeManager`; `create` factories return the owner; everyone else holds a handle/weak id | last, once the leaf layers are done; `destroy_instr` becomes the one place an object leaves the manager | update ORDER and RNG consumption order (determinism, `[SIMID v1]`); save-game object ids and ordering (`saveload*`); the destroy invariant row stays |
| ABL | the interpreter environment owns its modules and symbol tables; allocation is a `std::pmr::monotonic_buffer_resource` per module/compile unit (the pattern is real: many small immutable nodes freed together) behind an owner type; the three UserHeaps (symbol/stack/code) become members of it | after UserHeap batches; debugger `char* dest` buffers become `std::span<char>`/string (LG12b ledger item) | ABL source/compile semantics and the saved ABL state in save games (format), `.abl` scripts are mod content |
| gosFX | `EffectLibrary` owns specifications; `Effect::Make` returns `unique_ptr<Effect>` with the library-bound deleter; pools stay only if profiling says so | small; no format change | the `.fx` stream; GPU particles sample the gosFX CPU simulation, so object lifetime/age must not change |
| MLR | OUT OF SCOPE (owner ruling: MLR is the live effects path until GPU particles reach parity, then deleted wholesale, queue item 13). Only the audit's UB repairs (done) and anything the all-targets build forces | none | deletion is cheaper than migration; do not spend a batch on files with a retirement date |
| GameOS (Image, fonts, shader_builder, vulkan islands) | value owners (`std::vector<uint8_t>`, `std::unique_ptr<T[]>`), RAII GL/VK handle owners (`gpu_buffer_owner` pattern already exists) | leaf files first, with the GL/VK ownership rows already on the board | none |

## 3. Audit step-4 items re-scoped under this lens
UserHeap "thin facade, then std::vector" becomes delete-without-facade (nothing needs arena semantics; the facade would preserve the quirk). MemoryStream "bounds check" becomes a span-based reader (the check is then structural). EString "stays an ABI for gui" is withdrawn: it migrates with the widgets. EList "per site" stands, with the order contract written down per batch. MLR leaves the list; gosFX shrinks to its factories; ABL gains an arena owner (the one place an arena earns its keep).

## 5. Proof per batch (objhash does NOT apply: codegen changes)
1. Compile of the touched TUs + `tools/build_all_targets.py` (the tools are rebuilt in the same batch). 2. Doctest tier under ASan: add `MC2_ASAN` to `tests/unit` (`/fsanitize=address`, via cmake/Mc2Standalone.cmake) and run it every batch. 3. New `tests/unit/alloc_probe.cpp` (replaces global operator new/delete in the test binary, counts live allocations) + `ScopedLeakCheck`; every migrated leaf class gets a create/copy/move/destroy test asserting zero live allocations afterwards and a double-destroy-safe test. 4. Live counters in the game: `MC2_ALLOC_STATS` relaxed atomics in `gos_Malloc/gos_Free/operator new/delete` (gameos.cpp), line `[ALLOC_STATS v1] phase=mission_ready|exit live_allocs= live_bytes= peak_bytes=`; a board row ratchets `live_allocs` at exit per smoke mission DOWN only (baseline file, mc2_03/mc2_24/mc2_10). 5. smoke-lite every batch, tier1 every third, ASan smoke (`run_smoke_asan.py`, mc2_01, 30 s, zero new reports against asan-triage.md) every batch that touches game objects or UI. 6. Behaviour identity: `py -3 tools/sim_determinism.py run <mission> --baseline` on mc2_03, mc2_16, mc2_24 (two runs identical, graded and visual chain equal to `tests/smoke/sim_determinism_baseline.json`; the strict digest hashes raw float bits and may move only in a batch that touches float code, with the reason written down), run with `MC2_SMOKE_FREEZE_ANIM=1` for captures, `tools/log_identity.py` shapes on mc2_03/mc2_24, day+night A/B captures for any batch that touches rendering or appearance (viewed, MAD is not a signal).

## 6. Batching order (leaf utilities first; one subsystem and at most 25 files per batch, an Opus review of each batch before the next)
B0 harness: alloc_probe, ASan unit tier, `MC2_ALLOC_STATS`, SIMID baselines, a pointer-ordering scan. B1 EString to std::string (the type, its tests, the mclib/code users that are not widgets). B2 EList and the mclib value containers (DynamicArrayOf, BitFlag, MemoryBlock), then PriorityQueue/SortList behind the tie-order oracle. B3 files and streams (File family, MemoryStream to span reader, gosFX loaders). B4 UserHeap removal in mclib (move_globalmap_* first: 56 sites, pure arrays), then terrain/texture heaps, ABL heaps last. B5 shared assets (TG shapes, appearance, ClassData, ObjectType caches). B6 UI widgets with the screens. B7 game objects and their manager. B8 gosFX factories, ABL environment. GameOS leaf files ride along with the batch that touches their callers.

## 7. Risks and how each is caught
Double free hidden by `delete` of a pointer another subsystem also frees (P3): each batch lists every free site of a type before changing its owner; ASan + alloc_probe catch the second free. Array vs scalar mismatches: `new[]` becomes `vector`/`unique_ptr<T[]>`, mismatches become compile errors (the audit's 7 editor sites are already repaired). Exception safety under `/EHsc`: engine code is not exception-safe today; `std::bad_alloc` from `operator new` already throws (gameos.cpp), a throwing constructor now unwinds instead of leaking; keep `noexcept` on destructors and move operations, no new throws in game loops. Static-init order: pre-main statics (the LG19 reads) must not own heap objects whose constructors read other statics; function-local statics only. Address-dependent behaviour once allocations change: grep `std::map<[A-Za-z_:]*\*`, pointer `<` compares and pointer hashing; the SIMID digest and the order-liveness fixtures catch the rest. Class-level `operator new` going away: `make_shared` bypassed it already, `new T` did not; since both are malloc nothing observable changes. Moved-from objects in UI lists and handle invalidation in the object manager: handles carry a generation. The AppearanceType/shape caches are shared with the editor target (`gameos_editor`): the all-targets build covers it.

## 8. Exit criteria
LG03 ratchet to a floor of the named exceptions (TG_GOSVertexPool, ABL arena, MLR until deleted, third-party code), `systemHeap`/`UserHeap` symbols gone, `live_allocs` at exit monotonically down with the final number recorded, unit tier green under ASan, SIMID unchanged, tier1 5/5, captures viewed.

## 9. Decision points for the owner (external tools we do not build)
1. Is the C++ surface of mclib/Stuff (EString, File, MemoryStream, UserHeap) a supported API for external modder tools? If yes, a one-release compatibility header is needed; if no, the in-repo rebuild is the only compatibility we keep. 2. Do external tools read `.fx` files through our `MemoryStream` ABI or through their own parser? (The bytes stay either way.) 3. MLR: confirm it gets no ownership work. 4. May `MC2_ALLOC_STATS` ship compiled in (relaxed atomics on every allocation) or only in the proof builds?
Answered by the owner 2026-10-11: in-repo tools are rebuilt with the API they use (not a constraint); only formats, determinism and mod CONTENT are hard; an API break for an EXTERNAL tool is a decision for the owner (questions 1 and 2 above stay open); MLR gets no ownership work (3 answered); question 4 is open.
