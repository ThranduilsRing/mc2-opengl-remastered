# C++23 step 4: ownership, designed as we would write it today (PLAN; Opus design review 2026-10-11 APPROVE-WITH-CHANGES, folded in below; B1 blocked on the three prerequisites in section 11)

Lens (owner): not "wrap today's pointer flows in unique_ptr". Per subsystem: (a) the ownership model we would choose, (b) the path there, (c) what legacy shape must stay and why. Hard constraints are only on-disk/binary formats, gameplay determinism and mod CONTENT. In-repo tools (mc2fx, asset_viewer, mech_import, tg_import_dump, launcher, data_tools) are rebuilt against the new API in the batch that changes it (`tools/build_all_targets.py` is the proof). Anything that would break an EXTERNAL tool we do not build is a decision point (section 9), not a design input. Review detail and sources: `cxx23-step4-review.md`.

Fuller counts incl. editor/ and gui/: `new T` 1118, `new T[]` 362, `delete` 1048, `delete[]` 373, placement new 121, class-level `operator new/delete` 225 lines, `gos_Malloc/malloc/calloc/free` 320, `systemHeap->Malloc/Free` 320, already smart pointers 10. By directory (new / new[] / delete / delete[]): code 465/54/430/61 (UI screens: pilotreviewarea 53, mechlopedia 36, objective 34, salvagemecharea 19; 93 `systemHeap->` sites; 104 class-level operator lines); mclib root 131/19/237/13 (183 malloc-family, 213 heap-api sites led by move_globalmap_* 56, 28 per-subsystem `new UserHeap/HeapManager`); mclib/mlr 204/149/111/148; mclib/stuff 46/21/44/22 (placement new in memoryblock, sortedchain); mclib/gosfx 47/0/26/0; GameOS 47/86/67/103; editor 165/15/121/12 (Objective 29, Editor.cpp 23); gui 9/18/9/14.
Patterns: (P1) owned member pointers freed in destructors or `destroy()` (UI widgets, ~150); (P2) list items handed to a container that deletes them; (P3) factories freed by a registry elsewhere (ClassData 61, AppearanceType 4, TG_TypeMultiShape 27, MLRShape 22 + AttachReference/DetachReference); (P4) `new T[n]` + a separate length field; (P5) files and streams (`new File` 29, FitIniFile 17, PacketFile 6, ABLFile 6); (P6) per-subsystem arenas: 28 UserHeap/HeapManager plus class operator new routing to `systemHeap`/`objectCache`; (P7) bespoke containers (DynamicArrayOf 40, SortList, PriorityQueue, EList, Stuff chains); (P8) game objects in per-type pools.
Facts that shape the design: the shipped heap IS malloc (`USE_GOS_HEAP` always defined; `gos_Malloc`=malloc; global `operator new` = gos_Malloc), so no heap has arena semantics today, BUT it is not "just malloc" at the edges: `UserHeap::Malloc` returns null when uninitialised (heap.cpp:353-365) and class operators guard on `heapReady()` (section 7). No DLL boundary: every engine target is a static library; the only DLL is the string resource `mc2res_64.dll` plus delay-loaded FFmpeg (own allocator). Standalone tools each define their own `systemHeap`/stubs.

## 3. Audit step-4 items re-scoped under this lens

## 7. Risks and how each is caught
"Both are malloc, nothing observable changes" is FALSE: `AppearanceType::operator new` returns null when its heap is not ready (apprtype.cpp:72-80, UB on use) and its `delete` skips the free once the heap is torn down; 9 `heapReady()` guards (collsn 5, apprtype 2, appear 2) encode the same assumption. Migration deletes those operators, so each batch lists the guards it removes. Heap teardown frees NOTHING today (`gos_DestroyMemoryHeap`, gameos.cpp:199; "reclaimed with the cache", objmgr.cpp:246): moving to owners turns "reclaimed with the heap" into destructors that never ran, so the risk is use-after-free and teardown order, not leaks; each owner gets a written teardown order and ASan on the reload path. Double free through a pointer another subsystem also frees (P3): each batch lists every free site first (`own_inventory.py`). Exception safety under `/EHsc`: engine code is not exception-safe; a throwing constructor now unwinds instead of leaking; destructors and moves are `noexcept`, no new throws in game loops, and bad_alloc terminates (section 12). Static-init order: pre-main statics must not own heap objects; no static-duration owners. Address-dependent behaviour: grep `std::map<[A-Za-z_:]*\*`, pointer `<`, pointer hashing; SIMID and the liveness fixtures catch the rest. Moved-from objects in UI lists and handle invalidation in the object manager (generation handles). The AppearanceType/shape caches are shared with the editor target: the all-targets build covers compile, B7e covers behaviour.

## 12. After-migration requirements
Raw aliases into owned objects (objList, watchList, moverList, team rosters): destructors of migrated types are protected with the owner as friend, and an `own_inventory` gate fails any delete of a migrated type outside its owner. Converting `MechWarrior::brain` to `unique_ptr` before the instance-ownership fix would hide the borrowed-after-load case, so it waits. About 188 null checks after `Malloc` become dead code: delete them, do not wrap. A `set_terminate`/new handler writes the crash bundle (bad_alloc aborts silently today, the mc2_15 class); no exceptions as policy. No static-duration owners: explicit Game/Mission objects with a written teardown order. Portability: ALLOC_STATS lives in an opt-in portable TU; the ASan wiring gets a clang/gcc arm; the `DeleteFile` seam above.
